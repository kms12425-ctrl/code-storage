# AdaBoost 实现计划

## 1. 实现路线

1. 先定统一接口。无论后面使用对数几率回归还是决策树桩，都强制满足同一个接口：训练时接收 `X`、`y`、`sample_weight`，预测时输出 `{-1, +1}`。这一步是核心，因为 AdaBoost 本体不应该关心弱学习器内部细节。
2. 先做数据层。写一个数据读取与预处理模块，负责读取特征和标签、把标签统一映射成 `{-1, +1}`、手写 10 折划分、返回每一折的训练集和测试集。这里要兼容两种标签文件名：新要求偏向 `target.csv`，但当前样例和评测脚本仍然使用 `targets.csv`。
3. 先实现决策树桩，再实现对数几率回归。原因是树桩更容易调通 AdaBoost 的权重传递和误差更新，适合先验证主流程；等主流程稳定后，再接逻辑回归这个更容易受学习率、标准化、正则化影响的弱学习器。
4. 再写 AdaBoost 主体。它只做四件事：初始化样本权重、调用弱学习器训练、计算本轮加权错误率和 `alpha`、更新样本分布并保存集成器。
5. 最后接主入口。主入口负责读取命令行参数、选择基学习器编号 `0` 或 `1`、执行 10 折并输出 `1/5/10/100` 轮对应的预测文件到 `experiments` 目录。提交版代码不要强行创建该目录，题目已经明确说评测时会预建。

## 2. 建议的类和模块划分

1. 数据工具模块：负责读取 CSV、标签编码、手写 shuffle 和 10 折切分、必要时做训练折标准化。
2. 弱学习器模块：里面放 `DecisionStump` 和 `LogisticRegression` 两个类，它们都实现同样的 `fit` 和 `predict`。
3. AdaBoost 模块：负责集成训练、阶段性预测、保存每一轮的 `alpha` 和弱分类器。
4. 主入口脚本：解析参数，运行某一种弱学习器的实验，并输出结果文件。

## 3. 两个弱学习器的实现思路

### 3.1 决策树桩

训练目标是找到一个特征、一条阈值、一个方向，使加权分类误差最小。实现时对每个特征扫描候选阈值，并比较两种方向：

1. 小于阈值判为 `+1`，反之判为 `-1`。
2. 小于阈值判为 `-1`，反之判为 `+1`。

误差直接按样本权重加总，这部分用纯 NumPy 就能完成。

### 3.2 对数几率回归

使用带样本权重的二分类逻辑回归，标签统一成 `{-1, +1}`。优化目标建议使用加权对数损失：所有样本的 `w_i * log(1 + exp(-y_i f(x_i)))` 之和，再加一个较轻的 `L2` 正则项。

训练方式采用批量梯度下降即可，不需要复杂优化器。为了稳定，最好只对训练折做标准化，再将同样的均值和方差用于该折测试集。预测时对线性输出取符号。

## 4. AdaBoost 主体的关键细节

1. 初始样本权重统一设为 `1 / n`。
2. 每一轮都把 `sample_weight` 传给弱学习器。
3. 计算当前弱学习器的加权错误率 `error`。
4. 对 `error` 做裁剪，避免出现 `0` 或 `1`，建议截断到一个很小的正数和 `1 -` 该正数之间。
5. 按标准公式计算 `alpha`。
6. 更新样本权重并归一化。
7. 保存每轮弱学习器和 `alpha`，预测时做加权投票并取符号。

## 5. 最关键的工程点

1. 内部统一使用 `{-1, +1}`，不要在 AdaBoost 内部混用 `0/1` 和 `-1/+1`。
2. 训练到 `100` 轮时，不要分别重训 `1`、`5`、`10`、`100` 四次。更高效的做法是每折只训练一次到 `100` 轮，同时缓存第 `1`、`5`、`10`、`100` 轮的集成预测。
3. 如果逻辑回归精度不够，先检查三件事：是否做了训练折标准化、学习率是否过大、正则是否过强。
4. 决策树桩通常更容易先达到可用精度，逻辑回归更依赖数值稳定性。
5. 输出文件必须严格两列：第一列是从 `1` 开始的样本原始编号，第二列是预测标签。

## 6. 推荐的落地顺序

1. 先完成数据读取、标签编码和 10 折划分。
2. 用决策树桩接通 AdaBoost 主流程，先只跑 1 折、1 轮，验证文件格式是否正确。
3. 再把 10 折和 `1/5/10/100` 轮全部输出流程跑通。
4. 然后接入逻辑回归弱学习器。
5. 最后调逻辑回归的学习率、迭代轮数和正则强度，争取让 `T = 100` 时两个基学习器都稳定超过 `80%`。

## 7. 验证计划

1. 先做格式验证：确认 `experiments` 下四组文件都生成，且每个文件都只有两列、编号从 `1` 开始。
2. 再做功能验证：本地运行样例评测脚本。
3. 再做兼容验证：确认主入口支持命令行形式的 `data` 路径、`target` 路径、基学习器编号。
4. 最后做精度验证：重点看 `T = 100` 的结果。

## 8. 额外提醒

当前样例评测脚本里仍然使用了 `np.int`，在新版本 NumPy 中可能报错。实现代码本身不要使用这个旧别名；如果后面要本地跑样例评测，可能需要顺手把评测脚本中的 `np.int` 改成内置 `int` 才能稳定验证。
