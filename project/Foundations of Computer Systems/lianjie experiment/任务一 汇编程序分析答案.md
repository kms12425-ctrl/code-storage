# 汇编程序分析答案

以下分析基于本实验中的 `main.c` 与 `main.s`，结合具体变量和具体指令说明全局变量、局部变量以及函数调用在汇编程序中的表达方式。

## 1. 全局变量在汇编中的表示方式，以及 `.data` 段与 `.bss` 段的区别

在汇编程序中，全局变量通常先声明符号属性，再给出数据内容，常见形式如下：

```asm
.globl  符号名
.type   符号名, @object
.size   符号名, 字节数
符号名:
    初始化内容
```

### 1.1 已初始化的全局变量放在 `.data` 段

例如源程序中的：

```c
char init_gstr1[12] = "U202490042";
```

其对应汇编为：

```asm
.globl  init_gstr1
.data
.align 8
.type   init_gstr1, @object
.size   init_gstr1, 12
init_gstr1:
    .string "U202490042"
    .zero   1
```

这里之所以放在 `.data` 段，是因为该全局变量在定义时已经给出了明确初值。`"U202490042"` 连同结尾的字符串结束符一共占 11 个字节，而数组大小为 12 字节，因此编译器又补了 1 个字节的 0。

同类例子还有：

```c
int init_gv1 = 10;
int init_garr1[3] = {11, 12, 13};
int gv = NUMBER;
```

在汇编中分别表现为：

```asm
init_gv1:
    .long   10

init_garr1:
    .long   11
    .long   12
    .long   13

gv:
    .long   6
```

这说明：只要全局变量具有显式初值，编译器通常就会把它放入 `.data` 段。

### 1.2 未初始化的全局变量放在 `.bss` 段

例如源程序中的：

```c
char uninit_gstr2[12];
```

其对应汇编为：

```asm
.globl  uninit_gstr2
.bss
.align 8
.type   uninit_gstr2, @object
.size   uninit_gstr2, 12
uninit_gstr2:
    .zero   12
```

这里放在 `.bss` 段，是因为该变量没有显式初值。`.bss` 段表示“只分配空间但不在目标文件中写入实际初始数据”的区域，程序装载时默认清零，因此更节省目标文件空间。

同类例子还有：

```c
int uninit_gv2;
int uninit_garr2[3];
int *uninit_gp2;
int (*uninit_gfp2)(int, int);
```

在汇编中分别表现为：

```asm
uninit_gv2:
    .zero   4

uninit_garr2:
    .zero   12

uninit_gp2:
    .zero   8

uninit_gfp2:
    .zero   8
```

因此可以总结：

- 已初始化的全局变量，一般放在 `.data` 段。
- 未初始化的全局变量，一般放在 `.bss` 段。

### 1.3 特殊情况：带地址初值的指针变量

例如：

```c
int *init_gp1 = &init_gv1;
int *init_gp2 = &uninit_gv2;
int (*init_gfp1)(int, int) = fadd;
```

对应汇编为：

```asm
.section .data.rel.local,"aw"
init_gp1:
    .quad   init_gv1

init_gp2:
    .quad   uninit_gv2

.section .data.rel,"aw"
init_gfp1:
    .quad   fadd
```

这类变量虽然也是“已初始化的全局变量”，但它们的初值是符号地址，因此需要链接时重定位，所以编译器把它们放进带重定位属性的数据段，而不是普通 `.data` 段。

### 1.4 字符串常量通常放在 `.rodata` 段

例如：

```c
printf("sum = %d \n", sum);
```

对应汇编中字符串常量不是作为普通全局变量出现，而是：

```asm
.section .rodata
.LC2:
    .string "sum = %d \n"
```

说明字符串字面量通常被编译到只读数据段 `.rodata` 中。

## 2. 以函数调用语句为例，说明 C 语句与汇编语句的对应关系

在 x86-64 Linux 环境下，函数调用通常遵循 System V ABI 约定。前几个整型或指针参数依次放入 `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9` 中，返回值通常放在 `%eax` 或 `%rax` 中。

### 2.1 调用带一个参数的函数

源程序：

```c
check_gcc_condition(init_gstr1);
```

对应汇编：

```asm
leaq    init_gstr1(%rip), %rax
movq    %rax, %rdi
call    check_gcc_condition@PLT
```

对应关系如下：

- `leaq init_gstr1(%rip), %rax`：取全局数组 `init_gstr1` 的首地址。
- `movq %rax, %rdi`：把该地址作为第 1 个参数传入 `%rdi`。
- `call check_gcc_condition@PLT`：调用函数。

### 2.2 调用带两个参数的普通函数

源程序：

```c
sum = fadd(init_gv1, lv1);
```

对应汇编：

```asm
movl    init_gv1(%rip), %eax
movl    -12(%rbp), %edx
movl    %edx, %esi
movl    %eax, %edi
call    fadd@PLT
movl    %eax, -4(%rbp)
```

对应关系如下：

- `movl init_gv1(%rip), %eax`：取全局变量 `init_gv1` 的值。
- `movl -12(%rbp), %edx`：取局部变量 `lv1` 的值。
- `movl %eax, %edi`：把第 1 个参数送入 `%edi`。
- `movl %edx, %esi`：把第 2 个参数送入 `%esi`。
- `call fadd@PLT`：调用函数 `fadd`。
- `movl %eax, -4(%rbp)`：将返回值写回局部变量 `sum`。

由此可见，一条函数调用语句在汇编中通常会展开为“准备参数、执行调用、保存返回值”三步。

### 2.3 调用本文件中的静态函数

源程序：

```c
sum = fsub(50, 30);
```

对应汇编：

```asm
movl    $30, %esi
movl    $50, %edi
call    fsub
movl    %eax, -4(%rbp)
```

这里 `50` 和 `30` 是立即数，因此直接送入参数寄存器。由于 `fsub` 是本文件中的 `static` 函数，所以调用形式是直接 `call fsub`。

### 2.4 通过函数指针调用函数

源程序：

```c
sum = init_gfp1(50, 30);
```

对应汇编：

```asm
movq    init_gfp1(%rip), %rax
movl    $30, %esi
movl    $50, %edi
call    *%rax
movl    %eax, -4(%rbp)
```

这里先从全局函数指针 `init_gfp1` 中取出函数地址，再执行 `call *%rax` 间接调用。这与普通函数名调用相比，多了一步“先取地址”的过程。

### 2.5 调用变参函数 `printf`

源程序：

```c
printf("display init_gstr1 : %s \n", init_gstr1);
```

对应汇编：

```asm
leaq    init_gstr1(%rip), %rax
movq    %rax, %rsi
leaq    .LC1(%rip), %rax
movq    %rax, %rdi
movl    $0, %eax
call    printf@PLT
```

这里：

- `%rdi` 存放第 1 个参数，即格式串地址；
- `%rsi` 存放第 2 个参数，即字符串 `init_gstr1` 的首地址；
- `movl $0, %eax` 是调用可变参数函数前的 ABI 要求。

## 3. 用具体语句说明全局变量与局部变量在汇编表达形式上的差异

全局变量与局部变量在汇编中的最大差异，是访问方式不同：

- 全局变量通常通过“符号名 + `%rip` 相对寻址”访问。
- 局部变量通常通过“栈帧基址 `%rbp` + 偏移量”访问。

### 3.1 局部变量的表达形式

源程序：

```c
int lv1 = 15;
int lv2 = 17;
int sum = 0;
sum = lv1 + lv2;
```

对应汇编：

```asm
movl    $15, -12(%rbp)
movl    $17, -8(%rbp)
movl    $0, -4(%rbp)
movl    -12(%rbp), %edx
movl    -8(%rbp), %eax
addl    %edx, %eax
movl    %eax, -4(%rbp)
```

其中：

- `lv1` 位于 `-12(%rbp)`；
- `lv2` 位于 `-8(%rbp)`；
- `sum` 位于 `-4(%rbp)`。

这说明局部变量并没有独立的全局符号名，而是作为当前函数栈帧中的临时存储单元存在。

### 3.2 全局变量的表达形式

源程序：

```c
init_gv1 = 20;
uninit_gv2 = init_gv1;
```

对应汇编：

```asm
movl    $20, init_gv1(%rip)
movl    init_gv1(%rip), %eax
movl    %eax, uninit_gv2(%rip)
```

这里直接出现了符号名 `init_gv1` 和 `uninit_gv2`，说明全局变量在程序中拥有固定的静态存储位置，不依赖某个函数的栈帧。

### 3.3 全局字符数组与局部字符数组的差别

全局字符数组示例：

```c
strcpy(uninit_gstr2, "MaJunHao");
```

对应汇编中对目标数组的写入：

```asm
movq    %rax, uninit_gstr2(%rip)
movb    $0, 8+uninit_gstr2(%rip)
```

这里 `uninit_gstr2` 是全局数组，所以通过符号名直接访问。

再看函数 `fsub` 中的局部数组：

```c
char fmt[] = "static fsub : uninit_gv2 = %d \n";
```

对应汇编：

```asm
movq    %rax, -48(%rbp)
movq    %rdx, -40(%rbp)
movq    %rax, -32(%rbp)
movq    %rdx, -24(%rbp)
```

这些指令把字符串内容分块写入当前函数的栈空间，也就是说 `fmt` 作为局部数组，实际存储在栈帧内，而不是静态数据区。

### 3.4 函数内 `static` 变量兼具“局部作用域”和“静态存储”的特点

源程序：

```c
void fcount()
{
    int x = 0;
    static int count = 0;
    x++;
    count++;
}
```

对应汇编中：

```asm
movl    $0, -4(%rbp)
addl    $1, -4(%rbp)
movl    count.0(%rip), %eax
addl    $1, %eax
movl    %eax, count.0(%rip)
```

这里：

- `x` 是普通局部变量，用 `-4(%rbp)` 访问；
- `count` 虽然定义在函数内部，但因为是 `static`，其存储方式更接近全局变量，用 `count.0(%rip)` 访问。

在汇编末尾还能看到：

```asm
.local  count.0
.comm   count.0,4,4
```

说明 `count` 具有静态存储期，只是作用域限制在 `fcount` 函数内部。

## 4. 总结

通过本实验程序可以看出：

1. 已初始化的全局变量通常放在 `.data` 段，未初始化的全局变量通常放在 `.bss` 段。
2. 函数调用语句在汇编中会分解为“准备参数、执行 `call`、接收返回值”三个基本过程。
3. 全局变量通常以符号名形式出现，并通过 `%rip` 相对寻址访问；局部变量通常位于栈帧中，通过 `%rbp` 加偏移量访问。
4. 函数内部的 `static` 变量在作用域上属于局部，在存储方式上却属于静态存储区，因此汇编表现更接近全局变量。
