# 实验 机器级语言理解(二进制炸弹拆除) 操作说明

整个程序包含有：`bomb.c` `support.c` `phases.c` `support.h`。在老师手上有 `phases.c`，但同学们没有该源程序，而只有 `phases.o`。

提供给学生的包：`bomb.c` `support.c` `phases.o` `support.h`

由学生生成执行程序：

```bash
gcc -g -o bomb -D U2 bomb.c support.c phases.o
```

其中 `*` 为学号的最后一位。例如：学号为 `U202415001`，则使用命令：

```bash
gcc -g -o bomb -D U1 bomb.c support.c phases.o
```

运行程序：

```bash
./bomb
```


提醒：

1. 一定要输入自己的学号，运行结果中会显示学号的。
2. 在生成程序时，一定要带编译开关 `-D U*`；`*` 为学号的最后一位数字。

总答案：
```bash
U202490042
ABI Application Binary Interface.
2 4 7 12 20 33
4 284
14 7
m63487
2 5 6 3 1 4
```

第一关调试步骤：
```bash
set pagination off
break phase_1
run
# 程序会停在 phase_1 入口处，输入你的学号： U202490042
# 然后在断点处单步到计算完 rdx 的位置（call 前）
disas
# 找到 lea ... # <phase_1+0x46> 指令位置，记下它的地址或直接单步：
ni
ni
# 再查看寄存器 rdx 的值（rdx 应指向表项）
info registers rdx
x/s $rdx
display/i $rip
# 单步直到你看到指令变为 `add %rax,%rdx`（或紧接着的 `call`）
ni
ni
# 重复 `ni` 直到看到上述指令
# 然后查看寄存器和内存：
info registers rdx
x/s $rdx
```

第二关答案（学号 U202490042）：
```bash

```

第二关调试步骤（从“未知答案”推导，不是先知道再验证）：

思路：
1. 第二关先随便输入 6 个整数（例如全 0）。
2. 在每个 `cmp` 断点读取“程序期望值”的寄存器。
3. 把当前错误值改成期望值，让程序继续走到下一个检查点。
4. 循环结束后，栈里的 6 个整数就是正确答案。

这样做的意义：你是在“在线提取约束并修正输入”，不是拿已知答案去验证。

## A. 启动 gdb，并先停在第二关入口
~~~bash
gdb -q ./bomb
set pagination off
set disassembly-flavor intel

break phase_2
run
~~~

运行后输入：
~~~text
U202490042
ABI Application Binary Interface.
0 0 0 0 0 0
~~~

为什么先输 `0 0 0 0 0 0`：
- 目标是让 `read_six_numbers` 正常读入，先进入所有比较逻辑。
- 后面我们在断点处逐个改值，逐步“长出”正确答案。

## B. 在入口处查看汇编并布置精确断点
当停在 `phase_2` 入口时执行：
~~~bash
disas phase_2
display/i $rip

# 关键比较1：nums[0] 与 studentid[9]-'0'
break *phase_2+78

# 关键比较2：nums[1] 与 studentid[8]-'0'
break *phase_2+103

# 循环核心比较：nums[i] 与 nums[i-1]+nums[i-2]+1
break *phase_2+159

continue
~~~

为什么这些断点最关键：
- `+78` 和 `+103` 直接给出前两个数该是多少。
- `+159` 每次命中都会给出当前 `i` 的递推期望值。

## C. 命中 `phase_2+78` 后怎么做（推导第1个数）
此处是 `cmp %edx,%eax`，语义是“`nums[0]` 是否等于期望值”。

执行：
~~~bash
info registers eax edx
p/d $edx

# 把当前错误输入改成期望值，避免后续爆炸
set $eax = $edx
set {int}($rbp-0x20) = $edx

x/6dw $rbp-0x20
continue
~~~

为什么这样做：
- 这里 `edx` 就是程序算出来的“第1个数正确值”。
- 修改寄存器和栈中数组后，本次比较会通过，程序能继续。

## D. 命中 `phase_2+103` 后怎么做（推导第2个数）
同样是 `cmp`，语义是“`nums[1]` 是否等于期望值”。

执行：
~~~bash
info registers eax edx
p/d $edx

set $eax = $edx
set {int}($rbp-0x1c) = $edx

x/6dw $rbp-0x20
continue
~~~

为什么这样做：
- 这里 `edx` 给出第2个数的正确值。
- 继续采用“读期望值 -> 现场改值 -> 继续”的策略。

## E. 每次命中 `phase_2+159` 后怎么做（推导第3~6个数）
该处是循环核心比较，语义为：
`nums[i]` 是否等于 `nums[i-1] + nums[i-2] + 1`。

执行：
~~~bash
# 看当前是第几轮（i=2..5）
p/d *(int*)($rbp-0x24)

# 这里 eax 是“期望值”，edx 是当前 nums[i]
info registers eax edx

# 用期望值覆盖当前 nums[i]
set $i = *(int*)($rbp-0x24)
set $edx = $eax
set {int}($rbp-0x20 + 4*$i) = $eax

x/6dw $rbp-0x20
continue
~~~

为什么这样做：
- 在这条 `cmp` 前，程序已经把递推结果算到 `eax`。
- 所以 `eax` 就是当前这一轮 `nums[i]` 的正确答案。
- 这个断点会命中 4 次，对应 `i=2,3,4,5`，刚好推导出后四个数。

## F. 循环完成后读取最终六元组
~~~bash
x/6dw $rbp-0x20
~~~

你会读到完整答案：
~~~text
2 4 7 12 20 33
~~~

到这一步，你是通过调试过程“推导出答案”，而不是事先知道答案。

第二关快速验证命令：
```bash

```

第三关调试步骤（从“未知答案”推导，不是先知道再验证）：

思路：
1. 先用占位输入（如 `0 0`）让程序走进第三关逻辑。
2. 在“第1个数比较断点”读取期望值并修正第1个数。
3. 在“最终比较断点”读取程序算出的第2个数期望值并修正。
4. 由栈变量读出最终二元组，得到第三关答案。

这样做的意义：你是在调试过程中实时提取约束，而不是先猜答案再验证。

## A. 启动 gdb，并停在第三关入口
~~~bash
gdb -q ./bomb
set pagination off
set disassembly-flavor intel

break phase_3
run
~~~

运行后输入：
~~~text

ABI Application Binary Interface.
~~~

为什么先输 `0 0`：
- 只要能被 `sscanf` 读成两个整数，就能进入第三关全部比较路径。
- 后续在断点中改值即可，不会因为初始猜错而卡死。

## B. 在入口处反汇编并布置关键断点
停在 `phase_3` 入口后执行：
~~~bash
disas phase_3
display/i $rip

# 断点1：第1个数比较（cmp %eax,%edx）
break *phase_3+107

# 断点2：最终比较（cmp %eax,-0x10(%rbp)）
break *phase_3+257

continue
~~~

为什么这两个断点足够：
- `+107` 位置直接比较第1个输入和 `studentid+8-'0'`，可直接读出第1个数期望值。
- `+257` 位置比较第2个输入与程序已算好的目标值（存于 `[rbp-0x10]`），可直接读出第2个数期望值。

## C. 命中 `phase_3+107` 后怎么做（推导第1个数）
此处语义：`input1 ?= expected1`。

执行：
~~~bash
info registers eax edx
p/d $edx

# edx 是期望值，把输入1修正为 edx
set $eax = $edx
set {int}($rbp-0x18) = $edx

x/2dw $rbp-0x18
continue
~~~

为什么这样做：
- 断点处 `edx` 就是程序由学号字符换算出的第1个正确数字。
- 同步改寄存器和栈中输入值，可确保当前比较通过并继续执行。

## D. 命中 `phase_3+257` 后怎么做（推导第2个数）
此处语义：`input2 ?= expected2`，其中 `expected2` 已由前面的跳转表分支计算好。

执行：
~~~bash
p/d *(int*)($rbp-0x14)
p/d *(int*)($rbp-0x10)

# 把输入2修正为程序计算出的期望值
set $eax = *(int*)($rbp-0x10)
set {int}($rbp-0x14) = *(int*)($rbp-0x10)

x/2dw $rbp-0x18
continue
~~~

为什么这样做：
- `[rbp-0x10]` 是 switch/jump-table 分支写入的目标常量。
- 在最终比较前读取它，就等于直接读出第2个答案。

## E. 读取最终结果并形成答案
在断点2或通过后都可查看：
~~~bash
x/2dw $rbp-0x18
~~~

可得到：
~~~text
4 284
~~~

第三关快速验证命令：
```bash
printf 'U202490042\nABI Application Binary Interface.\n2 4 7 12 20 33\n4 284\n' | ./bomb
```

第四关答案（学号 U202490042）：
```bash

```

第四关调试步骤（从“未知答案”推导，不是先知道再验证）：

思路：
1. 先用占位输入（如 `0 0`）进入第四关。
2. 在调用 `func4` 之后的比较点，读到目标值是 `7`。
3. 通过 `func4` 的递归编码规则，推出第1个数必须是 `14`。
4. 在最终比较点读出第2个数也必须等于 `7`。

这样做的意义：不是凭猜测，而是先读取程序目标，再按函数语义反推出输入。

## A. 启动 gdb，并停在第四关入口
~~~bash
gdb -q ./bomb
set pagination off
set disassembly-flavor intel

break phase_4
run
~~~

运行后输入：
~~~text
U202490042
ABI Application Binary Interface.
2 4 7 12 20 33
4 284
0 0
~~~

为什么先输 `0 0`：
- 先确保 `sscanf` 能读入两个整数，让程序进入后续判断逻辑。
- 后续在断点里读取期望值并修正输入。

## B. 在入口处反汇编并布置关键断点
停在 `phase_4` 入口后执行：
~~~bash
disas phase_4
disas func4
display/i $rip

# 断点1：func4 结果与目标值比较点
break *phase_4+125

# 断点2：第2个输入与目标值比较点
break *phase_4+133

continue
~~~

为什么这两个断点最关键：
- `+125` 处执行 `cmp -0x10(%rbp), %eax`，即比较 `func4(input1,0,14)` 与目标常量。
- `+133` 处执行 `cmp %eax, -0x10(%rbp)`，即比较第2个输入与同一个目标常量。

## C. 命中 `phase_4+125` 后怎么做（推导第1个数）
先看当前比较双方：
~~~bash
info registers eax
p/d *(int*)($rbp-0x10)
~~~

你会看到：
- `*(int*)($rbp-0x10) = 7`（目标值）
- `eax` 是当前 `func4(input1,0,14)` 的结果

接着要找哪个 `input1` 让 `func4(input1,0,14)=7`。可直接在 gdb 里试函数：
~~~bash
p/d (int)func4(7,0,14)
p/d (int)func4(14,0,14)
~~~

你会看到：
- `func4(7,0,14)=0`
- `func4(14,0,14)=7`

因此第1个数确定为：`14`。

为什么这样做：
- 断点先给出目标值 `7`，然后用同一个函数现场求值，直接找出满足条件的 `input1`。
- 这比盲猜更稳定，也能对应汇编中的真实语义。

然后继续：
~~~bash
set {int}($rbp-0x1c) = 14      # 把第1个输入改成推导值
set {int}($rbp-0xc)  = *(int*)($rbp-0x10)   # 可选：保持局部变量一致
set $eax = *(int*)($rbp-0x10)  # 关键：让当前 cmp 通过
continue
~~~

## D. 命中 `phase_4+133` 后怎么做（推导第2个数）
此处是第2个输入比较点，执行：
~~~bash
p/d *(int*)($rbp-0x18)
p/d *(int*)($rbp-0x10)
set {int}($rbp-0x18) = *(int*)($rbp-0x10)   # 第2个输入 = target = 7
set $eax = *(int*)($rbp-0x10)               # 让当前 cmp 通过
~~~

你会看到目标值仍是 `7`，因此第2个数必须等于 `7`。

为什么这样做：
- 程序把目标常量放在 `[rbp-0x10]`，这一条比较直接要求第2个输入与它相等。

## E. 读取最终结果并形成答案
在断点2处可直接确认：
~~~bash
x/2dw $rbp-0x1c
~~~

应得到：
~~~text
14 7
~~~

第四关快速验证命令：
```bash
printf 'U202490042\nABI Application Binary Interface.\n2 4 7 12 20 33\n4 284\n14 7\n' | ./bomb
```

# 第二关到第六关：纯看汇编获取答案

这一部分不依赖在 `gdb` 里下断点，也不依赖“跑到比较点再读寄存器”。

核心思路是：
1. 直接看反汇编，恢复每一关的判定逻辑。
2. 需要常量表时，直接看可执行文件或目标文件的数据段。
3. 第二、第三关和学号有关，但汇编里已经明确告诉你“要取学号的哪一位”；把你自己的学号代进去即可。

建议使用的静态查看命令：

```bash
objdump -drwC bomb > bomb.asm
objdump -s -j .rodata bomb
objdump -s -j .data bomb
nm -n bomb
```

如果你只想看 `phases.o` 也可以，但第六关的链表值建议直接看最终生成的 `bomb`，这样不会被重定位和布局问题干扰。

## 第二关：可以直接从汇编静态推出

从 `phase_2` 的汇编可以直接读出三条约束：

```c
nums[0] == studentid[9] - '0';
nums[1] == studentid[8] - '0';
nums[i] == nums[i-1] + nums[i-2] + 1;   // i = 2..5
```

关键汇编含义如下：

```asm
a5:  movzx edx, BYTE PTR [rip+...]   ; 取 studentid[9]
af:  sub   edx, 0x30                 ; 字符转数字
b2:  cmp   eax, edx                  ; 比较 nums[0]

be:  movzx edx, BYTE PTR [rip+...]   ; 取 studentid[8]
c8:  sub   edx, 0x30
cb:  cmp   eax, edx                  ; 比较 nums[1]

fe:  add   eax, ecx
100: add   eax, 0x1
103: cmp   edx, eax                  ; nums[i] == nums[i-1] + nums[i-2] + 1
```

对学号 `U202490042`：

- `studentid[9] = '2'`，所以 `nums[0] = 2`
- `studentid[8] = '4'`，所以 `nums[1] = 4`

继续递推：

```text
nums[2] = 2 + 4 + 1  = 7
nums[3] = 4 + 7 + 1  = 12
nums[4] = 7 + 12 + 1 = 20
nums[5] = 12 + 20 + 1 = 33
```

因此第二关答案是：

```bash
2 4 7 12 20 33
```

## 第三关：可以直接从汇编静态推出

`phase_3` 先用 `sscanf(input, "%d %d", &x, &y)` 读两个整数，然后有两层约束。

第一层约束：

```asm
188: movzx eax, BYTE PTR [rip+...]
192: lea   edx, [rax-0x30]
195: mov   eax, DWORD PTR [rbp-0x18]
198: cmp   edx, eax
```

这表示：

```c
x == studentid[8] - '0';
```

对学号 `U202490042`，有 `studentid[8] = '4'`，所以第一个数必须是：

```bash
4
```

第二层约束是一个跳转表。虽然表本身是通过间接跳转实现的，但每个 case 的目标常量已经直接写在汇编里：

```text
x=0 -> y=2026
x=1 -> y=2401
x=2 -> y=123
x=3 -> y=654
x=4 -> y=284
x=5 -> y=789
x=6 -> y=425
x=7 -> y=99
x=8 -> y=100
x=9 -> y=321
```

其中与本题相关的是：

```asm
1f0: mov DWORD PTR [rbp-0x10], 0x11c
```

`0x11c = 284`，对应 `x = 4` 这一支。

因此第三关答案是：

```bash
4 284
```

## 第四关：可以直接从汇编静态推出

`phase_4` 的判定逻辑可以直接整理成：

```c
0 <= x <= 14;
target = 7;
func4(x, 0, 14) == 7;
y == 7;
```

其中 `target = 7` 是常量：

```asm
325: mov DWORD PTR [rbp-0x10], 0x7
```

而 `func4` 的汇编逻辑是标准的“二分查找路径编码”：

```c
int func4(int x, int low, int high) {
	int mid = low + (high - low) / 2;
	if (x < mid)  return 2 * func4(x, low, mid - 1);
	if (x > mid)  return 2 * func4(x, mid + 1, high) + 1;
	return 0;
}
```

现在要求：

```text
func4(x, 0, 14) = 7
```

因为 `7` 的二进制是 `111`，说明路径必须连续三次走右分支：

1. 区间 `[0,14]` 的中点是 `7`，要走右边，所以 `x > 7`
2. 区间 `[8,14]` 的中点是 `11`，还要走右边，所以 `x > 11`
3. 区间 `[12,14]` 的中点是 `13`，还要走右边，所以 `x > 13`
4. 区间 `[14,14]` 的中点是 `14`，此时命中，返回 `0`

所以唯一可行的第一个数是：

```bash
14
```

第二个数还必须等于目标常量 `7`，因此第四关答案是：

```bash
14 7
```

## 第五关：可以直接从汇编和数据段静态推出

这一关先检查输入串长度必须为 6：

```asm
39d: cmp DWORD PTR [rbp-0x14], 0x6
```

然后对每个字符做下面的变换：

```c
out[i] = array[input[i] & 0xf];
```

对应汇编：

```asm
3be: movzx eax, BYTE PTR [rax]
3c4: and   eax, 0xf
3c9: lea   rdx, [rip+...]     ; array.0
3d0: movzx edx, BYTE PTR [rax+rdx]
```

最后把变换后的 6 个字符与目标串比较：

```asm
3ef: lea rdx, [rip+...]       ; 目标串
3fc: call strings_not_equal
```

静态查看数据段后可得到：

```text
array.0 = "maduiersnfotvbyl"
target  = "bruins"
```

因此 6 个字符的低 4 位必须分别对应：

```text
b -> 13
r -> 6
u -> 3
i -> 4
n -> 8
s -> 7
```

也就是输入字符只要满足：

```text
input[i] & 0xf = 13, 6, 3, 4, 8, 7
```

这一关有很多组合法。给一个可直接输入、且全是可打印字符的答案：

```bash
m63487
```

验证一下低 4 位：

```text
'm' = 0x6d -> 0xd -> b
'6' = 0x36 -> 0x6 -> r
'3' = 0x33 -> 0x3 -> u
'4' = 0x34 -> 0x4 -> i
'8' = 0x38 -> 0x8 -> n
'7' = 0x37 -> 0x7 -> s
```

因此第五关可以用：

```bash
m63487
```

## 第六关：可以静态推出，但建议看最终 `bomb` 的数据段

第六关的逻辑分三步：

1. 读入 6 个整数。
2. 检查每个数都在 `1..6` 且互不重复。
3. 把这 6 个数当作“链表中的第几个节点”，按输入顺序重新连成一条新链表。
4. 检查新链表中的节点值是否按非增序排列。

最后的关键比较是：

```asm
578: mov edx, DWORD PTR [rax]        ; 当前节点值
586: mov eax, DWORD PTR [rax]        ; 下一节点值
588: cmp edx, eax
58a: jge 591                         ; 当前值 >= 下一值 才通过
```

也就是说，重排后的链表必须满足：

```text
node[0].value >= node[1].value >= ... >= node[5].value
```

这一关建议直接静态看最终 `bomb`：

```bash
nm -n bomb | grep node
objdump -s -j .data bomb
```

可恢复出 6 个节点的值：

```text
node1 = 281
node2 = 907
node3 = 322
node4 = 121
node5 = 824
node6 = 528
```

程序初始链表顺序是：

```text
node1 -> node2 -> node3 -> node4 -> node5 -> node6
```

因此输入数字 `k` 的含义就是“取原链表中的第 `k` 个节点”。

把节点按值从大到小排序：

```text
node2 = 907
node5 = 824
node6 = 528
node3 = 322
node1 = 281
node4 = 121
```

对应的位置序号就是：

```bash
2 5 6 3 1 4
```

因此第六关答案是：

```bash
2 5 6 3 1 4
```
